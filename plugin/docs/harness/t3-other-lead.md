# Lead on another provider

A lead that is not Claude Code reads this file once, after `t3-code.md`. Where a child runs, Seats on another family and Cursor-only features are sections of `t3-code.md`, in this folder, and paths here are relative to orbit's plugin folder, two levels above this file's folder.

Orbit's text uses Claude Code's names. A lead that is not Claude Code maps them with this table. Read it once, before the first spawn or T3 tool call.

| Claude Code | Lead on another provider |
| --- | --- |
| `Agent` with an `orbit:` `subagent_type` | Your native subagent tool with that agent, such as Grok's `spawn_subagent`, so no new top-level thread starts. Every orbit agent runs this way, code writers included, such as a serial `poteto-agent` delegate, except a child that Where a child runs sends to `delegate_task`. Never move a code child to another provider. With no native subagent tool, `delegate_task`. Beside that, `delegate_task` runs a same-provider child as Where a child runs says, and fills a panel seat on another family or the verifier seat. |
| `Agent` with an `orbit:` `subagent_type`, under a Codex lead | Codex's `spawn_agent` takes no agent type, so pass `fork_turns: "none"` and a brief that names the agent file, as A brief that names the agent file says. Wait on it with `wait_agent`. When your tool list has `close_agent`, call it once you have read the result, because a finished agent stays open and counts toward Codex's agent limit. Codex in T3 had no `close_agent` in a live lane, so skip it there without a line. |
| A brief to an orbit agent | Name orbit's plugin folder as an absolute path, two folders above the `rules` skill's base directory, because the agent's own paths may arrive unexpanded. A `delegate_task` brief also names the agent file to follow, `agents/<name>.md` in that folder, because a child thread loads no agent. It also says the child is a subagent of this thread, so it fills no roster seat and starts no child thread. |
| A brief that names the agent file | A brief to Codex's `spawn_agent` names the agent file and says the child is a subagent of this thread, as a `delegate_task` brief does, because `spawn_agent` cannot select an orbit agent either. Such a brief says to follow the file as the child's instructions. It tells the child to read that file in full before any other step, whatever the task's size, and to say in its report that it read the file. It says that `${CLAUDE_PLUGIN_ROOT}` in that file is the plugin folder. When the file's frontmatter limits `tools`, the brief states the limit, such as read-only for the advisor, because a hand-read file enforces none. |
| `${CLAUDE_SKILL_DIR}` in a skill body | That skill's own base directory. |
| `mcp__t3-code__<name>` | The bare name as your tool list shows it, such as `t3-code__<name>`. Under a Codex lead, `delegate_task` and `t3_thread_wait` sit on a second server, `t3-code-direct`, and the rest on `t3-code`. Orbit's text names T3 tools bare. |
| The `ToolSearch` probe | Your own tool search with the bare name, such as Grok's `search_tool`, then call the tool through it, such as Grok's `use_tool`. With no tool search, a T3 tool is present when its name is in your tool list. Otherwise the first real call is the probe, and an error means absent. Never call a tool with dummy arguments, because a dummy `delegate_task` starts a thread. |
| A model per role (`opus`, `sonnet`, `haiku`, `fable`, `inherit`) | The agent file's `model` field does not apply. Every spawn runs native on your own model, except as the next row says. Skip a Claude model (`opus`, `sonnet`, `haiku`, `fable`) that a Models cell or a skill names, such as interrogate's `model: "opus"` adversary, because you cannot run it, so the spawn takes the same default. Never send such a spawn to a Claude provider through `delegate_task`, because only a seat on another family leaves your provider. It runs on your own provider, as Where a child runs says. An `inherit` cell and every Effort cell still apply. Pass the effort that rules.md's "Match the model to the job" resolves as the native tool's effort field when it has one, such as Codex's `reasoning_effort`. With none, omit it and say so. Grok's `spawn_subagent` ignores the agent's `model`, so a Grok lead's code children run on its own model. That path has not run live. The reply names the model each spawn ran on. |
| A spawn on the `code` role, under a Codex lead | Pass `model: "gpt-6.1-sol"` to `spawn_agent`, and as `target.model` to a same-provider `delegate_task`. It stands in for `inherit`, the `code` role's default, so a `code` cell that says `inherit` keeps your own model. If `spawn_agent` rejects the model, or the model is unavailable, omit `model` and say so, as rules.md Workflow Defaults, Models says for a rejected model. Every other role, and the `code` role under any other lead, runs on your own model. |
| `run_in_background`, `TaskStop`, `Monitor`, `t3_background_wait` | The native equivalent. Every `delegate_task` call is `mode: "async"`, foreground or not, and carries a `clientRequestId`, as Where a child runs step 4 says. Then `task_status` after the wake and `task_cancel`. With none, skip with the line from Cursor-only features. |
| `TodoWrite`, `TaskCreate`, `TaskUpdate`, `TaskList` | The session's native task tools, such as Codex's `update_plan`. Follow `/orbit:start`'s list and status rules. T3 renders the native updates as task progress; no shared T3 task-list tool is needed. With no native equivalent, show progress as `/orbit:start` step 3 says. |
| `AskUserQuestion` | Your native question tool, such as Grok's `ask_user_question`. With none, a numbered question in the reply, recommended option first. |
| `AskUserQuestion`, under a Codex lead | Codex's `request_user_input` when it is in the turn's tool list. |
| `EnterWorktree`, `isolation: "worktree"` | As Where a child runs says. Outside T3, the native subagent's worktree option. With none, as under Codex's `spawn_agent`, run those units one at a time in the task worktree. |
| The SessionStart rules | The `rules` skill, which `/orbit:start` loads once per session. |
| Any other Claude-only tool a step names | Its native equivalent, else skip with the line from Cursor-only features. |
