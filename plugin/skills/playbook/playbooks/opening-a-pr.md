### Opening a PR

Invoked at the end of every other flow.

**Land.** The Land line in the project's Workflow block decides what opens. With no Land line, Land is `main`. Under Land `pr`, gitops pushes the task branch as `<type>/<slug>` and opens the PR with the title and description you wrote. Under Land `main`, gitops pushes nothing and opens no PR, and the branch stays local in the worktree. The reviewed units stay committed on the task branch in its worktree, unpushed, until `/orbit:ship` lands them.

Work from a git worktree off trunk, per the Worktree gate, and keep unrelated work out of it. gitops commits each reviewed unit by path, per the Delegate gate, and rebases them into small, landable commits, folding a later fix into its unpushed unit with fixup and autosquash. Run `/orbit:deslop` over the diff before commit and `/orbit:no-comments` before review.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`. Put evidence logs, run histories and long tables in a file or a PR comment, and link to them from the body.

Stack follow-ups by base branch. Under Land `main` no PR opens, so a stack is a chain of unpushed task branches, each child on its parent's exact tip. Open PRs ready. gitops runs `gh pr create` without `--draft`, then links the PR to this session's thread per the host adapter's built-in PR tool row (rules.md Delegation, **Host tools.**), and skips the link where `link_pull_request` is absent. Opening a PR does not start a babysit. **Ship by default** below starts it once the whole stack exists.

**Ship by default.** A change task ships unless the user opted out. Once the task's PR, or its whole stack, is built, run Babysit (`playbooks/babysit.md`) in `drive` mode to merge-ready under Land `pr`. It is `drive` even for a small or docs-only PR, because Shipping needs the watcher's terminal verdict. Then Shipping (`playbooks/shipping.md`). Under Land `main`, run Shipping. Shipping's independent verifier still gates every landing. "don't ship", "I'll land it" or "stack them, don't ship" opts out, and the task stops at the PR, or under Land `main` at the branch. Under a multi-phase plan, this default grants landing authority, so the plan runs `autopilot-full`. The opt-out withholds that authority, so the plan runs `autopilot-stack`. The plan's explicit go and its review gate still stop the run. A subagent that opens a PR returns to its parent without babysitting, and an autopilot owner babysits and stops where its brief says.

**Reply:** when the task shipped, Shipping's reply, and `Next: nothing pending.` once the whole run landed. After an opt-out, the PR URL, or under Land `main` the worktree path and branch so a later session can ship it, and `Next: /orbit:ship`.
