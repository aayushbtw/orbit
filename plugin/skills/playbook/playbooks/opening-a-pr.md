### Opening a PR

Invoked at the end of every other flow.

**Land.** The Land line in the project's Workflow block decides what opens. With no Land line, Land is `main`. Under Land `pr`, gitops opens the PR from the task branch `<type>/<slug>` with `pull_request_create`, which pushes the branch, using the title and description you wrote. Before the brief, read `t3_worktree_status` and give gitops the thread's bound branch, the task branch and its worktree path. gitops opens the PR only when the bound branch is the task branch. On a mismatch it pushes the task branch, opens no PR and reports both branches, per the host adapter's Open a PR row, and the reply names the mismatch. Under Land `main`, gitops pushes nothing and opens no PR, and the branch stays local in the worktree. The reviewed units stay committed on the task branch in its worktree, unpushed, until `/orbit:ship` lands them.

Work from a git worktree off trunk, per the Worktree gate, and keep unrelated work out of it. gitops commits each reviewed unit by path, per the Delegate gate, and rebases them into small, landable commits, folding a later fix into its unpushed unit with fixup and autosquash. Run `/orbit:deslop` over the diff before commit and `/orbit:no-comments` before review.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (rejected alternatives a reviewer would otherwise ask about, and the principles that drove a choice), `## Blast Radius`, `## Verification`. Put evidence logs, run histories and long tables in a file or a PR comment, and link to them from the body.

Stack follow-ups by base branch. Under Land `main` no PR opens, so a stack is a chain of unpushed task branches, each child on its parent's exact tip. Open PRs ready. gitops calls `pull_request_create` without `draft`, with `base` set to the parent's branch for a stacked PR, and that call links the PR to this thread (the host adapter's Open a PR row, rules.md Delegation, **Host tools.**). Each layer's brief carries the bound branch and that layer's branch, as **Land** says. When it cannot open a layer, as for a branch this thread is not bound to, gitops pushes that branch, opens no PR for the bound branch, and the reply names the layer's branch, per the adapter's Open a PR row. Opening a PR does not start a babysit. **Ship by default** below starts it once the whole stack exists.

**Ship by default.** A change task ships unless the user opted out. An active waiver (`SKILL.md` **Waivers**) outranks this default and every step below. `no commit`, `just testing` and `quick check` end the task before each commit, PR and landing they waive, and `no subagents` stops it at the PR or branch, because no verifier runs. When this playbook stopped at a pushed branch on a binding mismatch, no PR exists, so skip Babysit and Shipping and name the branch and the mismatch in the reply. Once the task's PR, or its whole stack, is built, run Babysit (`playbooks/babysit.md`) in `drive` mode to merge-ready under Land `pr`. It is `drive` even for a small or docs-only PR, because Shipping needs Babysit's terminal verdict. Then Shipping (`playbooks/shipping.md`). Under Land `main`, run Shipping. Shipping's independent verifier still gates every landing. "don't ship", "I'll land it" or "stack them, don't ship" opts out, and the task stops at the PR, or under Land `main` at the branch. Under a multi-phase plan, this default grants landing authority, so the plan runs `autopilot-full`. The opt-out withholds that authority, so the plan runs `autopilot-stack`. The plan's explicit go and its review gate still stop the run. A subagent that opens a PR returns to its parent after the work in its brief. No child watches a PR, and a child that did PR work ends with the PR line, per **Host watcher** in `playbooks/babysit.md`. An owner's build round reads its PR once with `pull_request_read` and returns with its PR line. The main thread links, babysits and lands it through `playbooks/autopilot-full.md`.

**Reply:** when the task shipped, Shipping's reply. After an opt-out, the PR URL, or under Land `main` the worktree path and branch, and tell the user to run `/orbit:ship` when ready.
