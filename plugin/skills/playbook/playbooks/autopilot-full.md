### Autopilot-full

**The main thread owns the queue, verdicts and landing. One owner at a time writes each PR in its worktree. Nothing merges until an independent verifier proves the patch.**

Under Land `main`, a PR means an unpushed task branch, the Check run stands in for CI, and landing pushes `HEAD:main` per Shipping.

1. **Take the operator's go.** The grant covers the queue's items. Items the operator reserves and PRs outside the queue stop at merge-ready. A request to state the plan is not a go. Track each item's base SHA, owner, acceptance check, head and blocker in the trail, not in the reply. On go, read enough to brief the first owner and start it. Each owner reads the sources for its own item.
2. **Delegate each build at the start.** Use a `general-purpose` child with role `implementation` on the `judgment` model (rules.md Workflow Defaults, Models), per the host adapter's Where a child runs. The brief names the item, base SHA, allowed paths, acceptance check, trail path and absolute paths of `SKILL.md`, `../../rules.md` and `../../rules-shared.md`. The owner runs `/orbit:start <item>` with the Skill tool and may use native foreground subagents. Start the trail in `$TMPDIR/orbit-autopilot/<slug>/<item>.tsv` with the worktree path and branch in its first row. Commit each finished unit before starting the next.

   Rebase onto current trunk, run the repo's checks for the touched paths, and append `code-ready <sha>` after Opening a PR's cleanup passes. Under Land `pr`, the owner opens the PR from its bound branch per `playbooks/opening-a-pr.md`, reads its state once with `pull_request_read` and returns with `PR <url>, head <sha>, checks and reviews <state>`. Under Land `main`, it returns the proven, unpushed task branch. Either way it reports its head SHA, worktree path, branch and proof. Settle the child once its result is in and keep its worktree for fixes. Keep the brief and trail there so a fresh owner can take over. Append `head <sha>` for every later head.
3. **Roll independent items through the queue.** Run owners in parallel off trunk under the Parallel cap (rules.md Workflow Defaults). Start the next ready item as a slot opens. Without `delegate_task`, owners run one at a time as Where a child runs says, and the reply says the tick cannot fire while one runs.
4. **Handle results and verify.** Link each opened PR. Run `playbooks/babysit.md` in drive mode from the main thread and start verification at the code-ready head while CI runs. Before ending a turn on a PR watch, advance any other ready item. Give each real blocker to a fresh fix round in the owner's worktree per Where a child runs, with the current head, finding and check. Fix rounds stay on the code-ready base unless trunk conflicts, breaks CI, or lands a known concurrent change to the same files. A rebase or fix that updates a published branch uses `git push --force-with-lease=<branch>:<sha>` pinned to the SHA the owner last pushed or took over. If another writer moved the branch, report it before pushing.

   Swarm-verify the code-ready patch once per `/orbit:swarm`, with independent lanes on the `code` model. Brief each lane from step 1 of `playbooks/shipping.md`, with its distinct question and the evidence it needs. Use an export of the named SHA for a lane that only reads. Include a live lane that proves the load-bearing behavior on the real surface and a diff review that checks for regressions and broken project rules. A clean verdict requires the live lane and your audit of the owner's proof. Use the repo's CI for routine checks that it already covers at the head. Under Land `main`, run the Check line on the head. When the `other-family` Models row lists providers, the main thread adds the read-only audit seat per the host adapter's seats file (`../../docs/harness/t3-seats.md`). A clean verdict need not wait on that additive seat. Check each finding before it blocks.

   Another full swarm runs for new behavior, a redesign or a large new diff. For a minor fix or conflict resolution, have one independent verifier check the affected behavior at the new head. A wording-only change or an unchanged patch can carry its live verdict when Shipping step 3 permits it. Every head still needs its own green checks. Under Land `pr`, post the verdict as Shipping step 1 says. Block only on a bug a user would hit, a failed gate or a wrong shipped doc the patch introduced or newly reaches. Anything that loosens a gate needs a verifier's proof and your fresh countersign. Restore a disabled or soft-failed check before landing. Never bypass a forge approval.
5. **Land from the main thread.** Under Land `pr`, wait for Babysit's `READY`, green checks and a clean verdict. Apply Shipping steps 3, 4 and 7 for patch identity, merge with read-back, and cleanup. Read and merge by PR number and current head. Under Land `main`, land a task branch with a passing Check run and a clean verdict using Shipping's Land `main` paragraph. Gitops can run a rebase or cleanup in the owner's worktree at your direction. Rebase when trunk conflicts or the changes that would land were never tested. When trunk changes a dependency or caller, run the patch's checks on the merge result. Carry a verdict forward only per Shipping step 3, and return to step 4 when a fresh verifier is needed. If trunk would force a third rebase, sequence the colliding work. Use Babysit's PR watch for a merge held by the forge.
6. **Advance on events.** Follow the host adapter's `next` and handle each child completion once. Act on its result and update the queue. On go for unattended work, or when the operator requests a tick, arm an hourly `schedule_task` bound to this thread, using the operator's interval when specified. Record each delegate's id, start and stuck-after runtime in the run store's `agents.tsv`. The tick reads that record and the trails and git side effects for stalls. A child waiting for a person needs an answer. Cancel a stuck child before replacing it. Stop the tick when the queue stops or finishes, and report only changes that need the operator's attention.
7. **Stand down at once on the operator's stop.** Send a hold to each running owner with `t3_thread_send` on its `childThreadId` as a zero-writes order. Keep each brief and trail. A stop cancels running delegates with `task_cancel`.

**Reply:** catch the operator up per `../ketchup/SKILL.md`. Give each PR's link and state, the verdict, what landed, open gates and parked follow-ups.
