Goal: $ARGUMENTS

Resuming from `/orbit:session-pickup`: mark the steps the prior trail finished as done.

1. **Pick the type** from the goal: `investigate` (a question, no change), `bug` (something broken), `feature` (new behavior), `refactor` (structure only), `prototype` (a throwaway sketch to make a design or behavioral decision cheaply, or to settle an empirical fork by observing it instead of asking the human: "prototype", "mock it up", "try this layout", "sketch it to decide"), `perf` (measured slowness), `hillclimb` (sustained improvement of one metric against a target; perf is a one-off fix), `autopilot-full` (a queue of independent changes run to merged with full autonomy), `autopilot-stack` (a queue of changes built and verified with full autonomy, delivered as one linear reviewed base-branch stack the operator lands), `multi-phase-plan` (a plan for work that spans phases or stacked PRs), `babysit` (an open PR driven to merge-ready: conflicts, review threads, CI). A large or cross-cutting effort (a migration across many call sites, an ambitious multi-part change), or work the user steps away from to trust later, routes to `/orbit:figure-it-out` even when a narrower flow like feature fits. Use `/orbit:figure-it-out` whenever no flow fits. A multi-phase or multi-PR plan, for work that spans phases or stacked PRs, routes to `multi-phase-plan`. When the output is a set of PRs, use `multi-phase-plan`, not `/orbit:figure-it-out`, which designs one bespoke run. A queue of independent PRs run to merged with full autonomy ("autopilot this queue", "full autopilot", one-owner-per-PR programs) routes to `autopilot-full`, not `/orbit:figure-it-out`, even when the user steps away. A queue delivered as one stack the operator lands ("autopilot-stack", "stack them, don't ship", "build the stack, I'll land it") routes to `autopilot-stack`, also not `/orbit:figure-it-out`. In a single change goal, "don't ship" or "I'll land it" keeps the flow and stops it at Opening a PR. Without them, a change ships by default, per **Ship by default** in Opening a PR. Any PR-status request ("babysit this", "get it green", "address the review comments", "check on PR X", "anything outstanding on X", "is it green") routes to `babysit`. Merely opening a PR never triggers it. Declare its mode before polling. Its step 1 owns the request-to-mode mapping. A request to land, ship or merge a ready change runs `/orbit:ship`. Green is not safe. Nothing gets armed before an independent verdict, and only the verified run lands. Ask only when the goal itself is unclear.
2. **Load the flow.** Run `/orbit:playbook <type>` with the Skill tool, or `/orbit:figure-it-out` or `/orbit:ship` when step 1 routed there. Copy its steps and gates into the todo list as written. For a change, **Opening a PR** follows the flow's steps, then, unless the user opted out, **Babysit** in `drive` mode under Land `pr` and **Shipping** last. A `prototype` is throwaway, so it ends at its **Reply:** with no Opening a PR, Babysit or Shipping. Its Principles and Stack rules hold for the whole task, and its **Reply:** sets what the final reply holds.
3. **Run the list in order.** Skip a step only by marking it `skip: <reason>`. Never drop one silently.
4. **Stay in the list.** "continue" or "do it" resumes it. "new task" starts a fresh list.
