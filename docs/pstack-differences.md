# Differences from pstack

Orbit copies pstack (`pstack/` in cursor/plugins). For Claude Code tool and path mappings, it follows pstack's adapter, `pstack/docs/harness/claude-code.md`. On a design fork, check pstack first. Record each difference here with its reason.

| Area | pstack on Claude Code | orbit | Why |
| --- | --- | --- | --- |
| Loading rules | The user runs `/pstack:poteto-mode` per task (`README.md`). | A SessionStart hook injects `rules.md` every session. poteto-mode's playbook routing becomes a `/orbit:start` rule. | Rules hold without the user remembering a command. No per-task command loads, so routing has to live in the rules. |
| Worktree for the main chat | "Work from a git worktree off main", no tool named (`playbooks/opening-a-pr.md`). It adds "Dirty branch with unrelated work: patch out, fresh worktree, apply. Snarled worktree: reset from main, redo minimally." | `EnterWorktree`. The worktree and its branch stay after landing, until `/orbit:worktree-cleanup` runs. The Worktree gate renames the branch to `<type>/<slug>` after entering. It carries both recovery sentences, and they override its skip-when-in-a-worktree rule. "Reset from main" becomes a fresh worktree. Either case runs `ExitWorktree` with `keep` first, then the gate again with a new slug. | Claude Code's worktree tools. gitops never runs `reset --hard`, so the gate swaps a snarled worktree for a fresh one off `origin/main`. `EnterWorktree` names the branch `worktree-<name>`, and a `/` in the name becomes `+`, so the name can't carry the branch. Opening a PR pushes `<type>/<slug>`, and the worktree-cleanup audit matches PRs by local branch name. |
| Running another skill | `Read` its SKILL.md by path, since the Skill tool refuses most pstack skills (`docs/harness/claude-code.md`). | Flow skills (start, playbook, ship, how, why, architect, interrogate, figure-it-out, unslop) and `worktree-cleanup` run through the Skill tool. Principles, `tdd`, `benchmark-checklist` and opt-in skills keep `disable-model-invocation` and are read by path or typed. | The flow chains skills, so they must be invocable. |
| Commits | No actor named. The delegate step says "Commit liberally" (`playbooks/feature.md` step 4). Feature says "Rebase into small, ordered commits" (`playbooks/feature.md` step 6) and refactoring "Rebase into small ordered commits" (`playbooks/refactoring.md` step 8), and `opening-a-pr.md` says to amend and rebase into small ordered commits. Bodies follow `technical-writing`. | The parent reviews each unit, then the `gitops` subagent (Sonnet) commits it, subject only. Unpushed fixes fold in with fixup and autosquash. Flow steps name the unit order instead of a rebase. Refactor delegates its units in step 8's order (subtraction, reshape, cleanup). Bug's failing repro is its own unit, committed before the fix unit. Opening a PR's **Commits** paragraph says the same. | Review before commit, and git output stays out of the main context. Units are committed in order as they pass review, so there is nothing to rebase. |
| Model per role | `setup-pstack` writes `~/.claude/rules/pstack-models.md` (`docs/harness/claude-code.md`). Flow text says "Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section" (`playbooks/bug-fix.md`, `feature.md`, `refactoring.md`, `perf-issue.md`, `hillclimb.md`). `poteto-mode/SKILL.md` Subagents says "Code delegates tier by difficulty." The hardest changes go to "your strongest judgment model" (`claude-opus-5-5-xhigh`), and "Trivial mechanical edits go to your fast code model" (`grok-4.7-xhigh-fast`, also the default code model). It adds "Verification is the exception and stays on the `swarm workers` model". "Match the model to the job" starts each role at "xhigh by default", raises one step "for the hardest or subtlest work", lowers "one step for judgment and two or more steps for routine work", and keeps verification on its own model and speed. | A fixed `model` in agent frontmatter. advisor defaults to Opus, gitops and verifier use Sonnet, comment-sicko inherits. The Delegate gate sets each code delegate's model per spawn: Opus for the hardest changes, Sonnet for the rest. rules.md's Delegation section ports "Match the model to the job" for every spawn, passed as the `Agent` call's `effort`. verifier keeps `effort: xhigh` in its frontmatter, advisor `high` and gitops `medium`. Flows drop their reasoning-level line, since rules.md covers every spawn. | Only Claude models exist here, so a per-role setup step adds nothing. Claude Code has no per-spawn speed, so the fast-mode sentence is dropped. The `Agent` tool takes `effort` when a skill or rules file asks for it. Sonnet stands in for pstack's fast code and swarm-worker model, Opus for its strongest judgment model. |
| Subagent type | "Use `subagent_type: "poteto-agent"` for any subagent you spawn inside a playbook step (code-writing delegates, ad-hoc helpers)", while routed skills (`how`, `why`, `interrogate`, `reflect`, `swarm`) keep their own (`poteto-mode/SKILL.md` Subagents). `readonly: true` maps to `Explore` (`docs/harness/claude-code.md`). | The same rule in rules.md's Delegation section, with `architect` in place of `swarm`. Orbit's old "Use the `Explore` agent for broad repo search" is gone. | `swarm` is not vendored, and orbit's `architect` spawns its own runners. |
| Task end | No handoff line. Feature work stacks its follow-ups (`playbooks/feature.md` step 6), and Autonomy proceeds on reversible work (`poteto-mode/SKILL.md`). | The same, plus one `Next:` status line. | The user's global CLAUDE.md asks for it. |
| Pausing | Always pause for force-push to shared branches, deploys, data deletion, customer messages (`poteto-mode/SKILL.md` Autonomy). | The same list, with any force-push in place of a force-push to a shared branch, plus a product call that's the user's. | Orbit never force-pushes. A product call is the one fork no experiment can settle (rules.md Task End). |
| Broken skill mid-task | Fix it in its own PR (`poteto-mode/SKILL.md`). | Fix it in its own commit. | Orbit lands on `main` by default. |
| Review | `interrogate` spawns one reviewer per configured model across families (Opus and Grok by default) and never auto-applies (`skills/interrogate/SKILL.md`). | `/orbit:interrogate` spawns two `general-purpose` reviewers, on Opus and Sonnet. pstack's are `readonly: true`; orbit's keep Edit and Write, and only the brief forbids edits. The trigger matches pstack: interrogate runs before shipping on a contested design, from feature step 8. There is no always-on review panel. | Only Claude models run in Claude Code, so diversity is across tiers, weaker than across families. |
| PR owner checks | "A subagent that opens a PR runs `/deslop` and `/no-comments`, and posts the URL". It returns without babysitting unless it is an Autopilot-full or Autopilot-stack owner, which is exempt from the rules that hold babysitting until a whole stack is built (`playbooks/opening-a-pr.md`). | The same rule with `/orbit:deslop` and `/orbit:no-comments`. Only an autopilot-full owner babysits, and it starts the loop once its PR is open. | Autopilot-stack is not ported, orbit opens no stacks, and an orbit owner reports no code-ready head. |
| Independent verifier | One verifier per PR, a Cursor cloud agent, runs the change with the matching control skill and posts PASS, PASS+NOTES or FAIL on the PR (`playbooks/shipping.md` step 1). | `agents/verifier.md`, a fresh `orbit:verifier` spawned by shipping step 1 (`/orbit:ship`) or the autopilot-full root. It returns its verdict, and gitops posts it on the PR with `gh pr comment`, with the SHA and the patch-id. It has no Edit or Write tool, though Bash can still write. It runs the project's `verify-*` skill when there is one, and drives prompt changes with `claude -p --plugin-dir` in a scratch repo. | Cloud agents don't exist in Claude Code. gitops runs every forge write. The prompt forbids edits to the worktree. |
| PR merges | Squash-merge bottom-up, one PR at a time, then read the PR back (`playbooks/shipping.md` step 4). | gitops merges with `gh pr merge` and the Land line's method, `--merge` by default, then reads back `state,mergedAt,baseRefName`. | One PR per task, no stacks. The merge method is the project's choice in its Workflow block. |
| Stale base on a PR | Report it and name the rebase. An Autopilot-full owner rebases its own branch and pushes with `--force-with-lease` (`playbooks/babysit.md` steps 4, 5, 7). | The same report. An autopilot-full owner under Land `pr` has gitops merge `origin/main` into its own branch and push instead. | Orbit never force-pushes, and a merge needs no force. |
| Opening a PR | `playbooks/opening-a-pr.md`, invoked at the end of every other playbook. Subagents inherit the worktree, or `git reset --hard` between `Task` calls. Commit liberally and rebase before opening PRs. PR text follows `/technical-writing`. The forge is `gh`, or Origin when its CLI resolves the repo, never Graphite. A built-in PR tool, when the run has one, does every PR write. Stacks are base-branch chains. Babysit waits until the phase or stack is built. The perf line links an arena or swarm directory. | The `## opening-a-pr` section, the last step of every change flow (Opening a PR gate). A **Land** paragraph opens a ready PR as `<type>/<slug>` under Land `pr`, and under Land `main` opens none and leaves the units committed on the unpushed task branch. Parallel delegates get their own worktree per the Delegate gate. gitops commits each reviewed unit, subject only. PR text keeps the STE rules inline, without `technical-writing`. `gh` is the only forge. The built-in PR tool paragraph is dropped. One PR per task, never a stack. Babysit runs only on request. The perf line drops the link. A **Reply** names the PR URL, or the worktree and branch, and the `Next:` line. | Orbit never force-pushes, and a stack needs `--force-with-lease`. Origin, Graphite, `technical-writing`, arena and swarm are not vendored. Claude Code has no built-in PR tool. Orbit lands on `main` by default, so the Land line decides whether a PR opens. |
| Babysit | `playbooks/babysit.md`. It replaces Cursor's built-in babysit skill. The forge is `gh` or Origin, each with its own stop conditions. The frontier is the lowest unmerged PR of a stack, with one babysitter per stack and a frozen queue list. An Autopilot owner rebases its own branch and pushes with `--force-with-lease`. Bugbot fixes go in the lowest PR that owns the code. The watcher is `scripts/watch-pr/watch-pr`. | The `## babysit` section, run on request. Under Land `main` it says there is no PR and stops. Fixes go through the Delegate gate in the PR's worktree. `gh` only, so the Origin paths are dropped. The frontier is the task's one PR. The built-in babysit sentence is dropped. The watcher is pstack's `watch-pr`, vendored in `skills/playbook/scripts/` and run with `bun`. An autopilot-full owner merges `origin/main` into its own branch instead of rebasing. Bugbot replies go through gitops, with the payload file written by the Write tool. | Origin is not vendored, and Claude Code has no built-in babysit skill. Orbit opens no stacks and never force-pushes. gitops runs every forge write and can write a file only through a shell command. |
| Shipping | `playbooks/shipping.md`. Each verifier is a Cursor cloud agent with a control skill, and posts its verdict on the PR. The verified run is the contiguous stack from the bottom. PRs land bottom-up with `--squash`, and each child is retargeted to trunk and pushed with `--force-with-lease`. The forge is `gh` or Origin. | The `## shipping` section, run on request through `/orbit:ship`. Each verifier is a fresh `orbit:verifier` briefed with an intent paragraph, and gitops posts its verdict, SHA and patch-id with `gh pr comment`. The run is the task's one PR, and the retarget step is dropped. The merge uses the Land line's method, `--merge` by default. Under Land `main` there is no PR. The verifier runs on the task branch, gitops rebases it onto `origin/main`, the Check line stands in for CI, the patch-id is compared, and gitops pushes `HEAD:main` in place of steps 4 and 5, never forcing. | Cloud agents, Origin and the control skills are not here. Orbit opens no stacks and never force-pushes. Orbit lands on `main` by default, so a change can ship with no PR. |
| Test before asking | Classify a fork, and sketch observable ones via the Prototype playbook. A full-autonomy grant decides calls it covers (`poteto-mode/SKILL.md` Non-negotiables). | Classify a fork and run the experiment. No Prototype playbook and no grant clause. | Prototype is not ported yet. |
| No matching flow | Route to `figure-it-out` when no bundled playbook fits, or for large, cross-cutting or step-away work. A standing multi-day program routes to Orchestrate (`poteto-mode/SKILL.md` Playbooks). figure-it-out's Start reads poteto-mode's Principles (`skills/figure-it-out/SKILL.md`). | `start` routes to `/orbit:figure-it-out` on the same triggers. No Orchestrate route. figure-it-out's Start reads the playbook's Principles, Stack rules and gates, and its last todo is **Opening a PR** when the run changes code. | Orchestrate is not ported yet. The gates keep a figure-it-out change on the same worktree, delegate and Opening a PR path as every other change. |
| Feature flow | `how`, `architect`, the throughput checkpoint, then the delegate (`playbooks/feature.md`). `interrogate` runs before shipping when the design is contested (step 7). A closing paragraph sends code-coupled work to a single owner who fans out internally, keeps parent-level fan-out for independent artifacts, and spawns a fresh owner rather than chaining interrupts. The delegate step says a subagent forbidden to spawn owns the diff directly, and "Comments per **Comments**". | A first step states "done" in 3 bullets ("Ask only if a real decision is missing"). Then `how`, `architect`, the throughput checkpoint, and the delegate. `interrogate` runs before shipping when the design is contested (step 8). The single owner is the parent, with one `orbit:poteto-agent` per unit under the Delegate gate. "That owner fans out internally after the blocking phase" is dropped. Artifact fan-out runs as read-only agents outside the Delegate gate. The forbidden-to-spawn clause and the Comments pointer are dropped. | Shipping step 1's intent paragraph and rules' Task End read the "done" bullets. Orbit's `poteto-agent` brief forbids spawning (`agents/poteto-agent.md`), an orbit rule, not a Claude Code limit, so only the parent can own and fan out, and the forbidden-to-spawn clause is always true. Artifact slices write no code, so the Delegate gate doesn't apply. Opening a PR's `no-comments` pass covers comments. |
| Architect runners | Phase B runs the `arena` skill with runners from `pstack-models.mdc` (Opus and Grok), cross-judged (`skills/architect/SKILL.md`). Feature delegates through `arena` when the implementation admits multiple valid shapes (`playbooks/feature.md` step 4). | Two `general-purpose` runners on Opus and Sonnet return their package in the reply, plus a third if the two aren't structurally distinct. The parent synthesizes. No arena cross-judge. Runners keep Edit and Write, and only the brief forbids edits. Feature runs `/orbit:architect` on a multi-shape choice before the delegate. | `arena` is not vendored, and only Claude models run here. |
| Perf artifacts | Cite the measurement in the PR (`playbooks/perf-issue.md` step 5). | The measurement is cited in the PR body when Land is `pr`, else in the reply. | Under Land `main` no PR opens, and commits are subject only. |
| Hillclimb | A subagent on the configured hillclimb model makes each attempt, and parallel attempts each get their own worktree. `decision.tsv` stays gitignored in the tree. An unattended run borrows the Autonomous run playbook's wake mechanism, and the run ends with Opening a PR (`playbooks/hillclimb.md`). | The `## hillclimb` playbook section. Each attempt is a fresh `orbit:poteto-agent`, and gitops commits each accepted fix by path. Parallel attempts follow the Delegate gate's parallel exception: `isolation: "worktree"`, and gitops cherry-picks a kept attempt onto the task branch. An unattended run borrows `/loop`'s wake mechanism. | Commits go through gitops, and delegates never commit. A delegate briefed per the gate works only in the path it's given, so an isolated attempt needs its own path and a way back to the task branch. Autonomous run is not ported, and `/loop` is Claude Code's wake mechanism. |
| Autopilot-full | One owner per PR, each a Cursor cloud agent, opens its PR early, reports the code-ready head before self-proof, pushes each finished unit, and merges once the root's swarm has verified it (`playbooks/autopilot-full.md`). The forge is `gh`, or Origin when its CLI resolves the repo, never Graphite. Trails and agent records go in "the root agent's store". Merge prep rebases, and an owner force-pushes its own branch with `--force-with-lease`. Swarm lanes prove behavior through `control-ui` or `control-cli`. Each tick re-reads the playbook "from trunk", and ticks and the reply catch the operator up per `ketchup`. | The `## autopilot-full` playbook section, routed by `start`. The root writes no code and runs none of the gates. Each owner is an `Agent` call with `general-purpose`, `model: "opus"` and `isolation: "worktree"`, briefed with its item, `origin/main` as its base, the playbook and `rules.md` paths, the grant, the babysit loop in `drive` mode, its trail path and the rule to stop at merge-ready. It runs `/orbit:start <item>`, which ends with Opening a PR, babysits, and returns at merge-ready, a PR the watcher reports `READY` under Land `pr` or a proven, unpushed task branch under Land `main`. Its report gives the head SHA, the patch-id, the PR link, the worktree path and branch, and its proof receipts. No PR opens early and no code-ready head is reported, so code-ready becomes merge-ready throughout, and Opening a PR's `deslop` and `no-comments` passes are the slop-strip. "Assume the VM dies" becomes "Assume the owner dies". Owners commit each unit instead of pushing it, the trail's first row names the worktree, and the first-tick stuck test reads commits, not pushes. Trails go to `$TMPDIR/orbit-autopilot/<slug>/<item>.tsv` and agent records to `agents.tsv` beside them. Step 4 is "Verify once", and its full swarm is a full check. That is one fresh `orbit:verifier`, briefed as shipping step 1 plus the Check line, and the root's own audit of the diff and the receipts. A lane is a verifier. A fresh owner without `isolation` takes each later round, a fix or the merge, and nobody messages a returned owner. The merge round runs only shipping steps 3 and 4 under the root's verdict. Under Land `pr`, gitops merges `origin/main` into the owner's own branch wherever pstack has the owner rebase, here or in babysit step 4, and nothing force-pushes. Under Land `main`, a PR is the task branch, the push of `HEAD:main` per shipping's Land `main` paragraph is the merge, and the Check run there stands in for CI. The project's `verify-*` skill is the control skill, and ticks probe each owner's subagents by trail rows, commits and pushes. Each tick re-reads the playbook without "from trunk", tells the operator what changed in plain words, and the reply drops `ketchup`. | Claude Code has no cloud agents. pstack's harness maps one to `isolation: "worktree"` with a named base, and `resume` to a fresh agent (`docs/harness/claude-code.md`). Claude Code subagents can spawn subagents (tested), so an owner runs its own delegates, gitops and verifier. A subagent reports once, when it returns, so the root can't verify a head before then (inferred). Subagents don't get the SessionStart output, so the brief carries `rules.md`. Orbit pushes nothing before Opening a PR and never force-pushes, so a dead owner's unpushed work stays in its local worktree. Full shipping would spawn a second verifier on a head the root already verified. Orbit lands on `main` by default, and its "gates" are the playbook's, so pstack's "re-run the gates" names the Check line. The playbook ships in the plugin, not the project's trunk. `swarm`, `ketchup`, Origin and the control skills are not vendored, and orbit's verifier judges only by running, so the root audits the diff. |
