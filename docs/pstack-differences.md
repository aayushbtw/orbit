# Differences from pstack

Orbit copies pstack (`pstack/` in cursor/plugins). For Claude Code tool and path mappings, it follows pstack's adapter, `pstack/docs/harness/claude-code.md`. On a design fork, check pstack first. Record each difference here with its reason.

| Area | pstack on Claude Code | orbit | Why |
| --- | --- | --- | --- |
| Loading rules | The user runs `/pstack:poteto-mode` per task (`README.md`). | A SessionStart hook injects `rules.md` every session. poteto-mode's playbook routing becomes a `/orbit:start` rule. | Rules hold without the user remembering a command. No per-task command loads, so routing has to live in the rules. |
| Worktree for the main chat | "Work from a git worktree off main", no tool named (`playbooks/opening-a-pr.md`). It adds "Dirty branch with unrelated work: patch out, fresh worktree, apply. Snarled worktree: reset from main, redo minimally." | `EnterWorktree`. The worktree and its branch stay after landing, until `/orbit:worktree-cleanup` runs. The Worktree gate renames the branch to `<type>/<slug>` after entering. It carries both recovery sentences, and they override its skip-when-in-a-worktree rule. "Reset from main" becomes a fresh worktree. Either case runs `ExitWorktree` with `keep` first, then the gate again with a new slug. | Claude Code's worktree tools. gitops never runs `reset --hard`, so the gate swaps a snarled worktree for a fresh one off `origin/main`. `EnterWorktree` names the branch `worktree-<name>`, and a `/` in the name becomes `+`, so the name can't carry the branch. Opening a PR pushes `<type>/<slug>`, and the worktree-cleanup audit matches PRs by local branch name. |
| Running another skill | `Read` its SKILL.md by path, since the Skill tool refuses most pstack skills (`docs/harness/claude-code.md`). | Flow skills (start, playbook, ship, how, why, architect, arena, interrogate, swarm, figure-it-out, unslop, technical-writing) and `worktree-cleanup` run through the Skill tool. Principles, `tdd`, `benchmark-checklist` and opt-in skills keep `disable-model-invocation` and are read by path or typed. As in pstack, the playbook's `SKILL.md` holds the gates, Principles and an index, and each flow lives in `skills/playbook/playbooks/<name>.md`, read only when it runs. | The flow chains skills, so they must be invocable. |
| Commits | No actor named. The delegate step says "Commit liberally" (`playbooks/feature.md` step 4). Feature says "Rebase into small, ordered commits" (`playbooks/feature.md` step 6) and refactoring "Rebase into small ordered commits" (`playbooks/refactoring.md` step 8), and `opening-a-pr.md` says to amend and rebase into small ordered commits. Bodies follow `technical-writing`. | The parent reviews each unit, then the `gitops` subagent (Sonnet) commits it, subject only. Unpushed fixes fold in with fixup and autosquash. Flow steps name the unit order instead of a rebase. Refactor delegates its units in step 8's order (subtraction, reshape, cleanup). Bug's failing repro is its own unit, committed before the fix unit. Opening a PR's **Commits** paragraph says the same. technical-writing's commit-body layer doesn't apply. | Review before commit, and git output stays out of the main context. Units are committed in order as they pass review, so there is nothing to rebase. A subject-only commit has no body to write. |
| Model per role | `setup-pstack` writes `~/.claude/rules/pstack-models.md` (`docs/harness/claude-code.md`). The hardest changes go to "your strongest judgment model" (`claude-opus-5-5-xhigh`), and "Trivial mechanical edits go to your fast code model" (`grok-4.7-xhigh-fast`, also the default code model). It adds "Verification is the exception and stays on the `swarm workers` model". "Match the model to the job" starts each role at "xhigh by default", raises one step "for the hardest or subtlest work", lowers "one step for judgment and two or more steps for routine work", and keeps verification on its own model and speed. | A fixed `model` in agent frontmatter. advisor defaults to Opus, gitops and verifier use Sonnet, comment-sicko inherits. The Delegate gate sets each code delegate's model per spawn: Opus for the hardest changes, Sonnet for the rest. rules.md's Delegation section ports "Match the model to the job" for every spawn, passed as the `Agent` call's `effort`. verifier keeps `effort: xhigh` in its frontmatter, advisor `high` and gitops `medium`. Flows drop their reasoning-level line, since rules.md covers every spawn. | Only Claude models exist here, so a per-role setup step adds nothing. Claude Code has no per-spawn speed, so the fast-mode sentence is dropped. The `Agent` tool takes `effort` when a skill or rules file asks for it. Sonnet stands in for pstack's fast code and swarm-worker model, Opus for its strongest judgment model. |
| Subagent type | "Use `subagent_type: "poteto-agent"` for any subagent you spawn inside a playbook step (code-writing delegates, ad-hoc helpers)", while routed skills (`how`, `why`, `interrogate`, `reflect`, `swarm`) keep their own (`poteto-mode/SKILL.md` Subagents). `readonly: true` maps to `Explore` (`docs/harness/claude-code.md`). | The same rule in rules.md's Delegation section, with the same routed skills. Orbit's old "Use the `Explore` agent for broad repo search" is gone. | Architect runs arena, whose runners are `poteto-agent`. |
| Task end | No handoff line. Feature work stacks its follow-ups (`playbooks/feature.md` step 6), and Autonomy proceeds on reversible work (`poteto-mode/SKILL.md`). | The same, plus one `Next:` status line. | The user's global CLAUDE.md asks for it. |
| Default landing | A task ends at Opening a PR. Babysit and Shipping run only on request ("Opening a PR does not start a babysit", `playbooks/opening-a-pr.md`; "Babysitting never authorizes merging", `playbooks/babysit.md` step 9). | A change task ships by default once the verifier passes it. It runs Opening a PR, then Babysit `drive` under Land `pr`, then Shipping. "don't ship", "I'll land it" or "stack them, don't ship" stops it at the PR or branch, as in pstack. A multi-phase plan defaults to `autopilot-full`, and the opt-out picks `autopilot-stack`. | User preference, 2026-10-29: "ill be writing more ship it when verified. than if it was dont ship until i say so". |
| Pausing | Always pause for force-push to shared branches, deploys, data deletion, customer messages (`poteto-mode/SKILL.md` Autonomy). | The same list, plus a product call that's the user's. | A product call is the one fork no experiment can settle (rules.md Task End). |
| Broken skill mid-task | Fix it in its own PR (`poteto-mode/SKILL.md`). | Fix it in its own commit. | Orbit lands on `main` by default. |
| Review | `interrogate` spawns one reviewer per configured model across families (Opus and Grok by default) and never auto-applies (`skills/interrogate/SKILL.md`). | `/orbit:interrogate` spawns two `general-purpose` reviewers, on Opus and Sonnet. pstack's are `readonly: true`; orbit's keep Edit and Write, and only the brief forbids edits. There is no always-on review panel. | Only Claude models run in Claude Code, so diversity is across tiers, weaker than across families. |
| PR owner checks | "A subagent that opens a PR runs `/deslop` and `/no-comments`, and posts the URL". The owner starts the loop once its PR is open. | An orbit owner reports no code-ready head. |
| Independent verifier | One verifier per PR, a Cursor cloud agent, runs the change with the matching control skill and posts PASS, PASS+NOTES or FAIL on the PR (`playbooks/shipping.md` step 1). | `agents/verifier.md`, a fresh `orbit:verifier` spawned by shipping step 1 (`/orbit:ship`) or the autopilot-full root. The prompt forbids edits to the worktree. |
| PR merges | Squash-merge bottom-up, one PR at a time, then read the PR back (`playbooks/shipping.md` step 4). | gitops merges bottom-up, one PR at a time, with `gh pr merge` and the Land line's method, `--merge` by default, then reads back `state,mergedAt,baseRefName`. | The merge method is the project's choice in its Workflow block. |
| Force-push | "Force-push only your own branch, with `--force-with-lease` pinned to the SHA you last pushed or took over" (`playbooks/autopilot-full.md` step 2). An owner publishes a rebase with `git push --force-with-lease` per that step (`playbooks/babysit.md` step 4), and shipping pushes a retargeted child "with `--force-with-lease`" (`playbooks/shipping.md` step 4). | gitops makes every force-push as `git push --force-with-lease=<branch>:<sha>`, with the SHA the lead passes, shipping's push included. It rewrites pushed history only on a task branch the session pushed or took over, never `main` or another session's branch, and stops if the remote tip differs (`agents/gitops.md`). | A bare `--force-with-lease` checks the remote-tracking ref, which any fetch moves, so it can overwrite a push nobody saw. gitops starts fresh each time, so only the lead knows the SHA. |
| Opening a PR | `playbooks/opening-a-pr.md`, invoked at the end of every other playbook. Subagents inherit the worktree, or `git reset --hard` between `Task` calls. Commit liberally and rebase before opening PRs. PR text follows `/technical-writing`. The forge is `gh`, or Origin when its CLI resolves the repo, never Graphite. A built-in PR tool, when the run has one, does every PR write. A stack is a chain of PRs, each targeting its parent's branch. Claude Code has no built-in PR tool. Orbit lands on `main` by default, so the Land line decides whether a PR opens, and under Land `main` there is no PR base to chain. |
| Babysit | `playbooks/babysit.md`. It replaces Cursor's built-in babysit skill. The forge is `gh` or Origin, each with its own stop conditions. Step 4 also bans a stack-wide submit. | Shipping | `playbooks/shipping.md`. Each verifier is a Cursor cloud agent with a control skill, and posts its verdict on the PR.
