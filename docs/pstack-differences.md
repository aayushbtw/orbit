# Differences from pstack

Orbit copies pstack (`pstack/` in cursor/plugins). For Claude Code tool and path mappings, it follows pstack's adapter, `pstack/docs/harness/claude-code.md`. On a design fork, check pstack first. Record each difference here with its reason.

| Area | pstack on Claude Code | orbit | Why |
| --- | --- | --- | --- |
| Loading rules | The user runs `/pstack:poteto-mode` per task (`README.md`). | A SessionStart hook injects `rules.md` every session. | Rules hold without the user remembering a command. |
| Worktree for the main chat | "Work from a git worktree off main", no tool named (`playbooks/opening-a-pr.md`). | `EnterWorktree`, then `ExitWorktree` after landing. | Claude Code's worktree tools, and ship removes the worktree after landing. |
| Running another skill | `Read` its SKILL.md by path, since the Skill tool refuses most pstack skills (`docs/harness/claude-code.md`). | Flow skills (start, playbook, ship, how, why, architect, interrogate, figure-it-out) run through the Skill tool. Principles, `tdd`, `benchmark-checklist` and opt-in skills keep `disable-model-invocation` and are read by path or typed. | The flow chains skills, so they must be invocable. |
| Commits | No actor named. The delegate step says "Commit liberally" (`playbooks/feature.md` step 4), and `opening-a-pr.md` says to amend and rebase into small ordered commits. Bodies follow `technical-writing`. | The parent reviews each unit, then the `gitops` subagent (Sonnet) commits it, subject only. Unpushed fixes fold in with fixup and autosquash. | Review before commit, and git output stays out of the main context. |
| Model per role | `setup-pstack` writes `~/.claude/rules/pstack-models.md` (`docs/harness/claude-code.md`). | A fixed `model` in agent frontmatter. reviewer and advisor default to Opus, gitops uses Sonnet, the rest inherit. Ship overrides the reviewer's model per spawn (Opus and Sonnet). | Only Claude models exist here, so a per-role setup step adds nothing. |
| Task end | No handoff line. Feature work stacks its follow-ups (`playbooks/feature.md` step 6), and Autonomy proceeds on reversible work (`poteto-mode/SKILL.md`). | The same, plus one `Next:` status line. | The user's global CLAUDE.md asks for it. |
| Pausing | Always pause for force-push to shared branches, deploys, data deletion, customer messages (`poteto-mode/SKILL.md` Autonomy). | The same list, plus gates a skill names (ship's manual-test go). | Ship's manual test needs the user. |
| Broken skill mid-task | Fix it in its own PR (`poteto-mode/SKILL.md`). | Fix it in its own commit. | Orbit lands on `main` by default. |
| Review | `interrogate` spawns one reviewer per configured model across families (Opus and Grok by default) and never auto-applies (`skills/interrogate/SKILL.md`). | `/orbit:interrogate` spawns two `general-purpose` reviewers, on Opus and Sonnet. pstack's are `readonly: true`; orbit's keep Edit and Write, and only the brief forbids edits. Ship keeps its own panel on every change: the `reviewer` agent on Opus and Sonnet in one message, findings merged with which-model tags, sorted per `lead-judgment.md`, and Act on fixed. | Only Claude models run in Claude Code, so diversity is across tiers, weaker than across families. |
| Independent verifier | One verifier per PR, a Cursor cloud agent, posts PASS, PASS+NOTES or FAIL (`playbooks/shipping.md` step 1). | `agents/verifier.md`, spawned fresh by ship's Verify step. It has no Edit or Write tool, though Bash can still write. It runs the project's `verify-*` skill when there is one, and drives prompt changes with `claude -p --plugin-dir` in a scratch repo. | Cloud agents don't exist in Claude Code. The prompt forbids edits to the worktree. |
| Docs-only skip | No ship-side skip. Babysit gives docs-only PRs a `check` pass, not `drive` (`playbooks/babysit.md` step 1). | Ship skips Check, Clean and Verify only for files no agent or runtime loads, such as a README. | Skills, agents and rules are prompts a runtime loads, so they still get verified. |
| PR merges | Squash-merge bottom-up, one PR at a time, then read the PR back (`playbooks/shipping.md` step 4). | Wait for CI, then merge with the Land line's method (default merge commit) and read back `state,mergeCommit`. | One PR per task, no stacks. The merge method is the project's choice in its Workflow block. |
| Stale base on a PR | Report it and name the rebase (`playbooks/babysit.md` step 5). | gitops merges `origin/main` into the branch and pushes. | Orbit never force-pushes, and a merge needs no force. |
| Test before asking | Classify a fork, and sketch observable ones via the Prototype playbook. A full-autonomy grant decides calls it covers (`poteto-mode/SKILL.md` Non-negotiables). | Classify a fork and run the experiment. No Prototype playbook and no grant clause. | Prototype is not ported yet. |
| No matching flow | Route to `figure-it-out` when no bundled playbook fits, or for large, cross-cutting or step-away work. A standing multi-day program routes to Orchestrate (`poteto-mode/SKILL.md` Playbooks). figure-it-out's Start reads poteto-mode's Principles (`skills/figure-it-out/SKILL.md`). | `start` routes to `/orbit:figure-it-out` on the same triggers. No Orchestrate route. figure-it-out's Start reads the playbook's Principles, Stack rules and gates, and its last todo is `/orbit:ship` when the run changes code. | Orchestrate is not ported yet. The gates keep a figure-it-out change on the same worktree, delegate and ship path as every other change. |
| Feature flow | `how`, `architect`, a throughput checkpoint, then the delegate (`playbooks/feature.md`). `interrogate` runs before shipping when the design is contested (step 7). | "done" bullets, `how`, `architect`, the data shape, then the delegate. No throughput checkpoint. `interrogate` runs on the architect sketch before the delegate when the design is contested. | The checkpoint is not ported yet. Ship's review panel runs the same rubric and models on the code right after, so interrogate moves to the sketch. |
| Architect runners | Phase B runs the `arena` skill with runners from `pstack-models.mdc` (Opus and Grok), cross-judged (`skills/architect/SKILL.md`). | Two `general-purpose` runners on Opus and Sonnet return their package in the reply, plus a third if the two aren't structurally distinct. The parent synthesizes. No arena cross-judge. Runners keep Edit and Write, and only the brief forbids edits. | `arena` is not vendored, and only Claude models run here. |
| Perf artifacts | Capture traces, compare the artifacts, and cite the measurement in the PR (`playbooks/perf-issue.md` steps 1, 4, 5). | Raw runs go under `$TMPDIR/orbit-perf/<slug>/`. The measurement is cited in the PR body when Land is `pr`, else in the reply. | Ship removes the worktree after landing, and commits are subject only. |
| Hillclimb | A subagent on the configured hillclimb model makes each attempt, and parallel attempts each get their own worktree. `decision.tsv` stays gitignored in the tree. An unattended run borrows the Autonomous run playbook's wake mechanism, and the run ends with Opening a PR (`playbooks/hillclimb.md`). | The `## hillclimb` playbook section. Each attempt is a fresh `orbit:poteto-agent`, and gitops commits each accepted fix by path. Parallel attempts follow the Delegate gate's parallel exception: `isolation: "worktree"`, and gitops cherry-picks a kept attempt onto the task branch. `decision.tsv` lives under `$TMPDIR/orbit-perf/<slug>/`. An unattended run borrows `/loop`'s wake mechanism, and the run ends with the Land gate. | Commits go through gitops, and delegates never commit. A delegate briefed per the gate works only in the path it's given, so an isolated attempt needs its own path and a way back to the task branch. Ship removes the worktree after landing, so an in-tree log would be lost. Autonomous run is not ported, and `/loop` is Claude Code's wake mechanism. |
| Flow wording | Bug step 1 reproduces via "the control skill (Non-negotiables)" (`playbooks/bug-fix.md`). Flow steps cite unvendored principles: build-the-lever, sequence-verifiable-units, separate-before-serializing-shared-state, foundational-thinking. | The project's `verify-*` skill is the control skill. Unvendored principles keep their claim in plain words, without the citation. The Worktree gate names hillclimb and figure-it-out runs by the commit type of what they change. | Orbit's control skill is `verify-*`. The unvendored principles have no file to read. Branch names must be commit types. |
| Vendored subset | 58 skills (`skills/`). | The subset in `skills.json`. | Unvendored skills are adopted when a flow needs them. |
